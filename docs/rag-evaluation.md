# ⚖️ ARCHITECTURAL GOVERNANCE: RAG EVALUATION & JUDGE SELECTION POLICY

## 1. Data Classification & Scope Policy (PII vs Public Data)

Enterprise X Corp enforces strict Data Sensitivity Classification across all AI workloads:

- **Tier 1 — Sensitive PII & Financial Data (100% On-Premise / Edge Cluster)**:
  - *Data Scope*: Account balances, CPF/CNPJ, PIX keys, transaction histories.
  - *Execution Policy*: Executed and monitored 100% locally inside the K3s cluster via Qwen 2.5 3B, IBM Granite Guardian 2B, and local PostgreSQL. **Zero data leaves the cluster.**

- **Tier 2 — Public Regulatory Knowledge (Offloaded External Judge)**:
  - *Data Scope*: Public Central Bank of Brazil (BACEN) resolutions (`BCB-142`, `BCB-103`, `BCB-001`).
  - *Execution Policy*: Evaluated asynchronously via **Gemini 2.5 Flash API**. 
  - *Architectural Rationale*: Evaluating public regulatory texts using an external LLM judge does not violate PII compliance because public regulations contain zero customer PII.

---

## 2. Methodological Bias Prevention (Self-Correlation Mitigation)

Using a local 3B model (Qwen 2.5 3B) as a judge for outputs generated by the same Qwen 2.5 3B introduces **Self-Correlation Bias** — where the evaluator shares the exact same reasoning blind spots as the generator.

By deploying **Gemini 2.5 Flash** as an independent, higher-capacity judge:
1. **Discriminative Evaluation**: Provides unbiased, highly accurate scoring of *Retrieval Relevance*, *Groundedness (Faithfulness)*, and *Answer Relevance*.
2. **Zero Local CPU Contention**: Offloads heavy evaluation loops from the 2 vCPU Oracle Cloud VM, reserving 100% of local CPU/RAM for real-time customer traffic and security guardrails.

---

## 3. High-Performance Asynchronous Client (`httpx.AsyncClient`)

Evaluation requests are dispatched asynchronously using a persistent, pooled HTTP client (`httpx.AsyncClient`) with strict JSON schema enforcement (`responseMimeType: "application/json"`).
